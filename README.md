# FES LIGHT — 音楽とスマホの演出スタジオ

管理者が音楽を読み込み、動画編集のように演出クリップを並べ、参加者のスマホの画面と背面ライトを操作するアプリです。

## 起動

Node.js 22以上で `npm ci` → `npm start`。管理者は `/admin.html`、参加者は `/client.html?event=main` を開きます。Renderでは Build Command を `npm ci`、Start Command を `npm start`（既存の `node server.js` でも可）にします。HTTPSがカメラ・画面スリープ抑止の前提です。

## 使い方

1. **準備・編集**で「曲を追加」を押すか、音源をドロップします。複数曲を一度に選択できます。「デモ曲で試す」なら16秒の合成音源と演出をすぐに試せます。
2. 波形や空き部分をクリックして再生位置を選び、「画面色」「虹色」「ライト点灯」「ライト点滅」「暗転」を追加します。
3. クリップをドラッグして開始位置を、右端をドラッグして長さを変更します。詳細欄では秒数、対象クラス、色などを数値で設定できます。複製・削除・元に戻す／やり直すにも対応します。
4. **試聴**は管理者の音楽と4クラスのスマホプレビューだけを動かします。好きな位置に移動して、その時点の画面色・ライト・点滅の位相を再現できます。
5. **参加・端末**で参加リンクを配ります。カメラ不要の「画面だけで参加」も選べます。QR表示は外部サービスへ参加URLを渡すリンクです。
6. **本番操作**で曲を選び「この位置から本番送信」を押すと、参加者へ演出を送り、管理者の端末で音楽を再生します。一時停止・再開・途中への移動にも対応します。会場の音響には管理者端末の音声を接続してください。参加者には音楽ファイルを配信しません。
7. **全員の演出を停止・暗転**は選択クラスにかかわらず現在の会場全体を止めます。本番送信中の編集・曲切り替えは停止後に行います。

## 保存と演出のルール

- 音源・波形・複数曲の演出は管理者ブラウザのIndexedDBへ保存します。タブを閉じても残りますが、ブラウザデータを消すと失われます。別の端末とは自動共有されません。
- 「演出をバックアップ」で全曲の演出をJSONに保存できます。音源は含まないので別途保管してください。読み込み後は各曲の「音源を再設定」で元のファイルを選びます。同名の未設定音源へ通常の追加から再接続することもできます。
- 以前の `my_timeline` が同じブラウザにある場合は取り込みボタンが表示されます。元データを残したまま、選択曲へ取り込みます。
- クリップはその長さの間だけ有効で、空白は黒画面・ライト消灯です。画面とライトは独立します。同じチャンネルが重なった場合は開始が後のクリップが優先され、終了後はまだ有効な前のクリップへ戻ります。同時開始の場合は後に追加した方が優先されます。
- 一時停止はその位置の画面・ライト状態を保持します。完全に消したいときは全員停止を使ってください。再生開始時には500msの準備時間を置き、音楽と演出が同じ時刻から進みます。
- 手動操作は曲の送信を停止し、色やライトの状態を直接変更します。タイムラインを再開するには本番送信を押します。
- 1曲2時間・150MB、演出2000個まで。ブラウザが再生可能な形式に限ります。波形が解析できない場合も、音源の再生と演出編集は利用できます。

## 同期と制約

サーバーが開始時刻・再生位置・演出を保持し、参加者は時刻の往復測定で時計の差を補正します。途中参加・再接続でも現在の位置を受け取ります。管理者の音源とプレビューも同じ再生位置を使います。曲の終了や送信者の切断では会場を暗転します。参加者が切断された場合もローカルで演出を止めます。通信が届かない場合に備えた30秒の応答監視もあります。

ブラウザのバックグラウンド制限、端末の負荷、回線、音声出力機器の遅延があるため、サンプル単位の同期は保証しません。本番前に会場の端末・音響で確認してください。背面ライトへの対応は機種・ブラウザに依存し、非対応でも画面のみで参加できます。既存システムと同様、この変更では管理者認証は追加していません。

## テスト

- `npm test` — 演出の状態復元、クラス指定、位相、入力検証、Socket.IOによる再生・停止・途中参加・会場分離・切断・自然終了。
- `npx playwright install chromium` のあと `npm run test:e2e` — 実ブラウザで音源取り込み・複数曲・ドラッグ編集・保存・途中試聴・本番送信・参加画面を確認。
